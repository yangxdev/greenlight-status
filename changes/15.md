# greenlight-status: change #15, Quick note drawer for ideas and evidence

> Change: yangxdev/greenlight#15 · Product: yangxdev/greenlight#5 · Spec it changes: blueprint.md

## Change

- **Quick note action.** Next to **New idea** in the Pipeline view's header (`src/features/board/Board.tsx`, the only
  place New idea lives; the request calls it "the Ideas screen") the owner gets a ghost **Quick note** button. It opens
  a `Drawer` with eyebrow "Quick note", title "Jot it down" and three fields: **Kind** (`Segmented`, options Idea and
  Evidence, Idea selected), **Note** (`TextArea`, required, hint "Idea: the problem and what you'd build. Evidence: what
  someone said, quoted, and who they are.") and **Links** (`TextArea`, optional, hint "One per line. The thread or post
  itself."). The one primary button is **File note**. Like New idea, the action is shown only to the signed-in owner.
- **Filing.** `POST /api/notes` (owner-only, same-origin, same checks as `POST /api/ideas`) creates an issue in the
  source repo as the owner, titled `[note] <first line of the note, at most 60 characters>`, label `note`, body exactly:

  ```
  ### Kind

  Idea

  ### Note

  <the note as typed>

  ### Links

  <the links, one per line, or _No response_ when empty>
  ```

- **What happens next.** After filing, the drawer replaces the form with a line and a link to the new issue: for Idea,
  "The Scribe turns it into an idea card in about a minute."; for Evidence, "Added to the field notes in about a
  minute." Footer: **Write another** (ghost) and **Close**.
- **Notes are not ideas.** Issues titled `[note] …` stay out of the Pipeline view, the project count, the filters and the
  stage strip until `notes.yml` retitles them `[idea] …`. The parser already ignores any title without the `[idea] ` or
  `[change] ` prefix; this change pins that with a test and does not rely on the label.
- **Rename.** In the New idea drawer the field "MVP in one day" becomes **MVP**, with the hint "The smallest first
  version that proves the value" (replacing "3–6 lines starting with “- ”."). The filed issue's section heading becomes
  `### MVP` to match greenlight's Idea form (`.github/ISSUE_TEMPLATE/idea.yml`, `label: MVP`), and the server's
  "required fields" error says "the MVP".

Stays exactly as it is: the New idea form's fields, validation, "Approve it now" option and behaviour; the Pipeline,
Ideas and project views; the change drawer; sign-in; all other routes; `GET /api/health`. No new secrets and no AI calls.

No change.

## Data model

No stored data. New request type in `shared/api.ts`; the response reuses `NewIdeaResponse`.

```ts
export const NOTE_KINDS = ['Idea', 'Evidence'] as const;
export type NoteKind = (typeof NOTE_KINDS)[number];

/** POST /api/notes: the Quick note form's fields. */
export interface NewNote {
  kind: NoteKind;
  note: string;
  /** One link per line; may be "". */
  links: string;
}
```

Worker rules (`worker/routes/write.ts`), same style as `validateIdea`:

- `kind` must be `Idea` or `Evidence`; anything else (or missing) is a 400 "Pick Idea or Evidence."
- `note` is trimmed for the check and must be non-empty (400 "Write the note first."); `note` and `links` are at most
  `MAX_FIELD` (5000) characters (400 "Keep each field under 5000 characters.").
- Title: the first non-empty line of the note, whitespace-trimmed, cut to 60 characters and trimmed again, prefixed
  `[note] `. The body's Note section holds the note as typed (outer whitespace trimmed only).
- Links: split on newlines, each line trimmed, blank lines dropped, rejoined with `\n`; none left means `_No response_`.

Old records: nothing existing changes shape. Idea issues already filed keep their `### MVP in one day` heading; nothing
in the dashboard reads that heading (the project page shows body sections by whatever heading they carry).

## Acceptance criteria

- **CH1:** Given the owner's session and a same-origin request, when `POST /api/notes` is sent with
  `{ kind: 'Idea', note: 'Bike shops keep paper cards\nso nobody knows…', links: 'https://a.example\n\n  https://b.example ' }`,
  then GitHub receives `POST /repos/<repo>/issues` as the owner with title `[note] Bike shops keep paper cards`, labels
  `['note']` and a body exactly `### Kind\n\nIdea\n\n### Note\n\n<the note>\n\n### Links\n\nhttps://a.example\nhttps://b.example`,
  and the response is 201 `{ number, url }`.
- **CH2:** Given a note whose first line is 100 characters long, when it is filed, then the title is `[note] ` plus at
  most 60 characters with no trailing space; given empty links, then the Links section is `_No response_`; given
  `kind: 'Evidence'`, then the Kind section is `Evidence`.
- **CH3:** Given a signed-out request, a stranger's session, a cross-origin `Origin`, or a Worker without sign-in set up,
  when `POST /api/notes` is sent, then the answer is 401, 403, 403 and 403 respectively and GitHub is never called.
- **CH4:** Given a body with a blank note, a `kind` other than Idea or Evidence, or a note or links over 5000
  characters, when `POST /api/notes` is sent, then it answers 400 with a message and GitHub is not called.
- **CH5:** Given GitHub answers 401 or 422, when a note is filed, then the Worker answers as `createIdea` does (401 clears
  the session cookie; other failures are 502 "GitHub refused: …").
- **CH6:** Given an issue titled `[note] Bike shops` labelled `note` among the source repo's issues, when `/api/status` is
  built, then `projects` has no entry for it and the project count does not include it; given the same issue retitled
  `[idea] Bike shops`, then it appears as an idea.
- **CH7:** Given `ideaBody`, when an idea is filed, then its body has `### MVP` (not `### MVP in one day`) and the other
  five headings are unchanged; a missing problem, users or MVP still answers 400 "Problem, target users and the MVP are required."
- **CH8 (must not break):** Given the existing New idea tests, when they run with the renamed label, then filing an idea
  with `approve: true` still creates the issue with label `idea`, adds `approved`, and answers 201; `POST /api/ideas`,
  `/api/projects/:number/changes`, actions and comments behave as before; `GET /api/health` still returns `{ ok: true }`.
- **CH9:** Given the drawer is open, then Kind shows Idea pressed, and Note and Links are empty; the only primary button
  is "File note".
- **CH10:** Given an empty Note, when "File note" is clicked, then "Write the note first." shows and nothing is sent.
- **CH11:** Given a note typed with Kind Idea, when "File note" is clicked and the API answers 201 `{ number: 21, url }`,
  then one request goes to `/api/notes` with `{ kind: 'Idea', note, links }`, the form is replaced by "The Scribe turns
  it into an idea card in about a minute." and a link to the issue's url; with Kind Evidence the text is "Added to the
  field notes in about a minute."
- **CH12:** Given the API answers an error, when "File note" is clicked, then the message shows in a `role="alert"`
  element, the typed note is kept and the button is usable again; given the success view, when "Write another" is
  clicked, then an empty form with Kind Idea shows.
- **CH13:** Given the owner is signed in, when the Pipeline view renders, then "Quick note" and "New idea" both show, and
  clicking "Quick note" opens the dialog; given a signed-out visitor, then neither action nor the drawer renders.
- **CH14:** Given the New idea drawer, then its field is labelled "MVP" with the hint "The smallest first version that
  proves the value", and "MVP in one day" appears nowhere.
- **CH15 (must not break):** Given the New idea drawer, when Name, Problem, Target users and MVP are filled and "File and
  approve" is clicked, then `/api/ideas` is called with `title`, `users` and `approve: true` and the project page opens;
  empty required fields still show their messages and send nothing.
